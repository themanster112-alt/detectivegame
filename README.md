# محرك التحقيق العربي — Godot 4.7.2

محرك تحقيق 2D بواجهة عربية RTL، للموبايل الأفقي 1280×720، بخط Noto Sans Arabic المضمّن وترخيصه. القضايا القصيرة تستهدف نحو 15 دقيقة كبيان تصميم فقط؛ لا يوجد مؤقت يوقف التحقيق.

## التشغيل

افتح project.godot واضغط F5. المدخل main.tscn، والواجهة scenes/investigation/investigation.tscn.

تبدأ القضية بملف الحادث، ثم التقرير، ثم إحاطة المساعد. بعدها يمكن التنقل وجمع الأدلة واستدعاء أي شخصية متاحة وطرح الأسئلة بحرية. زر الاتهام متاح منذ بدء التحقيق؛ لا يشترط جمع جميع الأدلة أو اتباع تسلسل بعينه.

يسجل الاتهام أولًا دون تصحيح الاسم. يطلب اللاعب مراجعة الملف لاحقًا، ويصدر قرار يستند إلى المواد التي أرفقها لحظة الاتهام. التدقيق الاختياري اللاحق وحده يكشف النتيجة الفعلية أو الحكم الخاطئ. يمكن إعادة فتح القضايا المسموح بها مع الاحتفاظ بالأدلة والاتهامات السابقة.

لوح التحقيق يعرض الأدلة والأقوال والأشخاص والتقارير وتحديثاتها والخط الزمني والاستنتاجات والفرضيات. الربط المسنود يثبت اتساق معلومات محددة، ولا يكشف هوية الجاني.

## إضافة قضية

1. استخدم data/templates/case_template.json نقطة بداية، وحدد معرّفًا فريدًا.
2. ضع الملف المكتمل داخل data/cases/. لا يوضع القالب نفسه ضمن قائمة اللعب.
3. عرّف الأشخاص والحقائق الثابتة وشروط المعلومات والتقارير وقواعد تقييم الاتهام.
4. عيّن visual_catalog_path إلى كتالوج أصول مستقل للقضية، أو اتركه فارغًا لعرض وسوم الصور المفقودة.
5. افتح القضية من «ملف القضية» أثناء اللعب.

[عقد البيانات وتفاصيل التأليف](docs/CASE_SCHEMA.md) · [بنية المحرك والحفظ والحوار](docs/ENGINE_ARCHITECTURE.md) · [الأصول والصور](docs/ART_ASSETS.md).

data/cases/midnight_training.json يظل مثالًا تجريبيًا بصيغته القديمة، ويحوّله legacy_case_adapter.gd إلى عقد المحرك العام دون تعديل محتواه. بيانات tests/fixtures/engine_contract.json اصطناعية لاختبار تنوع الأعداد وأنواع الجرائم، وليست قضية نهائية.

## الحفظ والحملة

يُحفظ التقدم تلقائيًا بعد تغيّره وعند تعليق التطبيق، داخل user://investigation_progress.json. لكل قضية تقدم مستقل مرتبط ببصمة ملفها، مع سمعة المحقق والثقة وسجل القرارات على مستوى الحملة. لا يستبدل النظام الحفظ التالف أو غير المطابق بصمت. لا توجد نسخ احتياطية؛ كتابة الحفظ تستخدم ملفًا مؤقتًا ثم استبدالًا ذريًا.

القرارات المعلنة منفصلة عن حقيقة الحكم. لا تظهر نتيجة مخفية عبر السمعة أو سجل الحملة قبل التدقيق الاختياري. يمكن لشروط القضايا التالية الاعتماد على القرار العام أو النتيجة المدققة.

## مزود الحوار

dialogue_provider.gd واجهة قابلة للاستبدال، وlocal_dialogue_provider.gd يعمل دون إنترنت. يحصل المزوّد فقط على معلومات الشخصية والصياغات المسموح بها عند السؤال الحالي. لا يتلقى حقيقة الجريمة أو الحقائق المقفلة. يتولى المحرك تطبيق الشروط والتحقق من الإجابة وتحديث التقدم، ولا يسمح للمزوّد بتغيير الجاني أو اختراع حقيقة.

لا توجد مفاتيح API أو اتصالات شبكية أو خدمات مدفوعة. أي دمج مستقبلي يمر عبر خادم موثوق، لا من تطبيق اللعبة مباشرة.

## الأصول والتصدير

خلفيتا المكتب والاستقبال وصور ليلى الموجودة محفوظة دون تعديل. ترتبط الخرائط بالقضية عبر مورد الأصول، ولا توجد أسماء أشخاص أو عدد مشتبه بهم مفروض داخل المحرك العام. الوسوم المؤقتة تبقى واضحة عند غياب الصور.

لم تُنشأ حزمة Android أو iOS في هذه المرحلة. عند التصدير ضمّن data/cases/*.json وموارد assets التي تُحمّل ديناميكيًا، واستبعد tests/ وdocs/ و.godot/. ما زال اختبار اللمس والاستئناف والأداء على هاتف فعلي مطلوبًا.

## الواجهة القصصية

تبدأ القضايا الجديدة بافتتاحية سينمائية، ثم ملف الحادث والتقارير وإحاطة المساعد، مع التالي والانتقال المباشر إلى الموقع. أدوات التحقيق نوافذ أصغر وبطاقات ذات صفحات وتبويبات، وزر توجيه اتهام يبقى متاحًا أثناء التحقيق. لم يتغير منطق المحرك أو بيانات القضايا. راجع [تقرير تجربة الواجهة](docs/UX_LAYOUT.md). وللتحقق من التنقل واللمس شغّل res://tests/test_ux_navigation.gd بالطريقة نفسها لبقية الاختبارات.

## فحص موقع الجريمة

الأدلة تُكتشف عبر مناطق فحص شفافة فوق عناصر الخلفية، دون أسماء أو صور أدلة مكشوفة في المشهد. تُعرّف المناطق لكل قضية عبر JSON أو كتالوج العرض، ويُجمع الدليل صراحة من نافذة الفحص. راجع [تعريف مناطق الفحص](docs/HOTSPOTS.md)، وشغّل res://tests/test_crime_scene.gd لاختبار المشهد واللمس والشريط السفلي.
